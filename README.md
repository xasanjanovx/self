# Self — личный Telegram-ассистент

Один бот для себя: **питание** (КБЖУ по фото/тексту/голосу), **финансы**
(доходы/расходы/долги/переводы + статистика по категориям) и **вакансии**
(оформление поста для канала @ishdasiz + промпт для картинки).

Стек: Python 3.12 · aiogram 3 · Supabase (async) · Gemini · Docker.

## Как устроено

```
bot/
  main.py          сборка бота, middlewares, фоновые задачи
  config.py        настройки из env
  context.py       синглтоны: settings / db / ai
  db.py            async-доступ к Supabase (постраничное чтение, без блокировок)
  cache.py         in-memory TTL-кэш на пользователя (сбрасывается при записи)
  services.py      данные для панелей одним вызовом + инвалидация кэша
  ai.py            Gemini: JSON-режим, thinkingBudget=0 для разбора, короткий retry
  categories.py    фиксированный справочник категорий (ключи + ru/uz названия + алиасы)
  finance.py       чистая логика финансов: балансы, статистика, локальный парсер
  nutrition.py     план КБЖУ, агрегаты дневника
  vacancy.py       детект вакансии, нормализация, сборка поста, промпт
  handlers/        menu · nutrition · finance · vacancy · analytics · inbox(fallback)
  screen.py        «один живой экран»: панель редактируется на месте, мусор удаляется
```

Принципы скорости:
- ни одного блокирующего вызова в event loop (Supabase и Gemini — async);
- данные панели читаются параллельно (`asyncio.gather`) и кэшируются;
- простые операции («такси 25000», «обед 40к, зарплата 5 млн») разбираются
  локально без AI; AI подключается только для долгов/переводов и сложных фраз;
- `callback.answer()` вызывается сразу — «часики» на кнопке не висят;
- бот пускает только `ALLOWED_TELEGRAM_IDS` (личный).

## Запуск локально

```bash
python -m venv .venv && .venv\Scripts\activate
pip install -r requirements-dev.txt
copy .env.example .env   # заполнить
python -m bot.main
pytest -q
```

## Supabase

1. `sql/schema.sql` — базовые таблицы.
2. `sql/migrations/001_settings_tables.sql` — профиль питания, счета, настройки отчёта (обязательно).
3. `sql/migrations/002_screen_message_id.sql` — чтобы меню не дублировалось после рестарта.
4. `sql/migrations/003_finance_category_keys.sql` — приведение старых категорий к ключам (по желанию).

Ключ — `service_role`, поэтому бот должен жить только в защищённой среде и с
`ALLOWED_TELEGRAM_IDS`.

## Деплой на сервер (Docker)

Бот живёт в `/opt/codex-bots/self`, контейнер `codex-self-bot` из
`/opt/codex-bots/docker-compose.yml` (`env_file: ./self/.env`).

С локальной машины (пушит `main` и пересобирает контейнер по SSH):

```bash
bash scripts/deploy_remote.sh
```

Или прямо на сервере:

```bash
bash /opt/codex-bots/self/scripts/deploy.sh
```

Логи: `docker logs -f codex-self-bot`.

## Использование

- **Финансы**: `такси 25000` · `обед 40к наличными` · `зарплата 5 млн` ·
  `дал в долг 200000` · `снял с карты 300000` · несколько операций через запятую ·
  вопрос: «сколько я потратил на еду в этом месяце?»
- **Питание**: фото блюда, «омлет из 3 яиц и кофе», голосом.
- **Вакансии**: текст/пересланный пост/фото с подписью → пост на узбекской
  латинице по шаблону канала + отдельным сообщением промпт для картинки (16:9).
  `VACANCY_CHANNEL=@канал` включает публикацию в канал одной кнопкой (бот — админ).
- **Аналитика**: 7/30/90 дней, графики калорий и категорий, авто-отчёт раз в
  неделю (вс 20:00) или раз в месяц.
